## OIDC trust — root cause & fix

Diagnosis chain (all confirmed this session):
- Workflow wiring is correct (reaches STS with right role/region/aud).
- Trust policy live state (via `aws iam get-role`) **does** contain
  `repo:transformteamsg/*` under `StringLike` sub, and `aud` = `sts.amazonaws.com`.
- Org login casing is lowercase `transformteamsg` (not a casing bug).
- IAM OIDC provider `ClientIDList` contains `sts.amazonaws.com` (not a provider bug).
- CloudTrail failed event had `roleArn: null` → rejection at token validation, not sub-list.
- **Debug step printed the actual `sub`:**
  `repo:transformteamsg@157443699/hello-beeline@1322510990:ref:refs/heads/main`
  → org has **immutable IDs** in the OIDC subject. `repo:transformteamsg/*`
  can't match (after `transformteamsg` comes `@157443699`, not `/`).

Why String-dxd apps still work: different org, no immutable IDs, standard sub
format matches their literal entries. Implication: **every** transformteamsg app
onboarded since the org enabled immutable IDs fails OIDC the same way. The
`transformteamsg/platform` "passing" build shown was almost certainly stale.

**Fix (edit made locally, NOT yet committed — commit was interrupted):**
File `infra/states/provider.aws/acct.mgmt/iam/github/terragrunt.hcl`, the
`enable_web_identity_statement.conditions.sub.values` list:
- Added `repo:transformteamsg@157443699/*` (org-ID-scoped; matches all repos in the org).
- Kept `repo:transformteamsg/*` as a fallback.
- Dropped stale `repo:String-dxd/hello-beeline:*` (repo migrated). Other
  `String-dxd/*` entries (onward, my-sec, covaa, sums, reliefcher,
  fsbb-calculator) **must not be touched** — they belong to other apps.

`157443699` is the **org** id → org-wide, not repo-specific. Repo-specific would
need repo id `1322510990`. **This is a mgmt change → commit → push → MR → tag
DevOps for approval (never applied directly).**

To audit *when* immutable IDs were enabled: org audit log (needs org-admin /
GHE audit-log access) — `gh api "/orgs/transformteamsg/audit-log?phrase=oidc"`
or Org → Settings → Logs → Audit log. Doesn't change the fix.
